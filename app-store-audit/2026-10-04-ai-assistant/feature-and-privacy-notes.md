# How to Adult assistant candidate: features, privacy and release notes

Prepared 2026-10-04 from the current native candidate sources. This is an implementation and release-planning note, not a claim that the new AI features have passed native QA or shipped. It does not change the existing README, backend, public privacy policy, App Store metadata or submitted release.

## What the candidate adds

The Assistant turns a task, optionally with a selected How to Adult guide, into a saved plan. Plans contain editable reminders, calendar blocks, research actions, shopping lists and checklists. The existing offline guides, bookmarks, checked steps and guide reminders retain their separate library. A plan draft does not claim its actions have already happened.

Two generation choices are implemented in source:

- **On device:** Apple Intelligence through Foundation Models, available only on iOS or macOS 26 when the system reports its model available. Compatible hardware, enabled Apple Intelligence and model availability still matter. The app does not silently switch an unavailable on-device request to a paid provider.
- **OpenAI API:** an optional API-key connection using the Responses API. The selected model must support the required structured output; research also requires web search. The source has a configurable model ID and a model-access check, which do not establish that every custom model works. API use, including applicable search-tool charges, is billed to the person's API account separately from their ChatGPT subscription. [OpenAI billing guidance](https://help.openai.com/en/articles/9039756-managing-billing-for-chatgpt-and-the-api-platform)

**Research with OpenAI** explicitly requests live web search. The response parser requires a completed search call, a completed response and actual provider URL-citation annotations. It validates those HTTPS citations and saves each researched action's sourced answer with its recorded check time; optional research before planning has its own plan-level evidence. The UI presents the answer with source links. Guide citations come from the selected guide's existing sources; generated prose containing a URL is not accepted as citation provenance. Research remains a separate explicit action, or an optional step before generating a plan. This implementation still needs authorized end-to-end provider validation before the feature is described as tested.

Reminders and calendar events can be applied individually after reviewing an action. Automatic application of new plans is independently opt-in for reminders and calendar events, off by default. Enabling either option first checks the relevant OS permission and does not itself create an item. Only newly generated actions with a future date are considered for automatic application; existing saved plans are not replayed. Turning off an automation leaves items already scheduled in place.

The default reminder destination is an app notification. Daily, weekly and monthly patterns are implemented, with a shared limit of 60 pending guide/assistant notifications including writes in flight. Repeating app notifications must start at the next matching local-calendar occurrence; a distant initial start is rejected because that OS trigger cannot express a separate start boundary. Monthly dates 29–31 skip months without that date. Notification delivery is performed by the OS after scheduling, not by an AI process at delivery time.

Calendar actions request write-only access and use the system default calendar. They do not inspect existing events or detect conflicts. The executor supports a preselected calendar identifier only with already-full event access, and optional export to a chosen Apple Reminders list only with full Reminders access. Those destination capabilities are executor support; the current Settings UI exposes default-calendar events and app notifications, without a calendar/list picker. A successful write records the real system identifier. An interrupted or uncertain write requires review rather than an automatic retry that could create a duplicate.

The **Make a life plan** App Shortcut runs the connected assistant when invoked. A person can add it to their own Shortcuts workflow or supported personal automation for periodic use. Execution remains subject to system automation behavior, provider/model availability, network and credential access. The candidate does not install an always-on AI scheduler or a hosted recurring-research service. Fresh research happens when the person or their Shortcut invokes it; previously scheduled notifications can still be delivered while the app is closed.

Shopping actions prepare an editable list, share it, and open a web search for the person's query. The optional **Find options with OpenAI** action sends the query/title and list items for live research using original retailer sources, then saves the cited answer for that shopping action. It instructs the provider not to invent location, prices or inventory. The current outbound link is a search link, not a merchant checkout integration. The person chooses the seller and completes any purchase outside the app. **List prepared** records preparation only. There is no autonomous merchant/order placement, payment authorization, guaranteed inventory check or purchase receipt integration in this candidate.

## Local storage and data leaving the device

Plans, action states, actual native receipts, saved research answers, citations and automation preferences are stored locally in `AssistantLibrary-v1.json`. This is separate from the existing `UserLibrary-v1.json` guide-progress file. There is no app-managed plan cloud sync. Native Calendar or Reminders records may follow the person's own Apple/system account settings; that is distinct from synchronizing the app's local plan library.

The OpenAI API key is saved in this device's Keychain with synchronization disabled and device-only, when-unlocked accessibility. It is not stored in a plan or sent to the catalog backend. It is used as the authorization credential for direct OpenAI API calls. Disconnect removes that saved key and resets the connection choice; it does not delete saved plans or items already added to native services. Provider/model/research choices use local app preferences.

With OpenAI selected, a requested plan sends the typed task, current time/time zone, selected guide excerpts and any research context used for that plan directly to OpenAI. An explicit research action sends its query to OpenAI's web-search tool; shopping research also sends that action's list items. Model-access testing also makes an authenticated request to OpenAI. The current generation context does not send the full guide-progress library, the entire saved-plan library or existing calendar/reminder contents. The Settings copy names OpenAI and explains task/guide transfer and separate API charges. Optional on-device generation does not use this OpenAI transport; explicitly choosing research with OpenAI can still use the saved API connection for that separate action.

The source sets `store: false` on Responses API requests. This must not be described as a zero-retention guarantee. OpenAI distinguishes response/application state from abuse-monitoring data and other feature-specific storage. Its current policy says API data is not used for training unless the customer opts in, while standard abuse-monitoring logs may retain content for up to 30 days, with stated legal and service-protection exceptions. The connected account's controls and applicable feature policies govern provider handling; this app has not established a Zero Data Retention approval for anyone's account. [OpenAI API data controls, checked 2026-10-04](https://developers.openai.com/api/docs/guides/your-data)

Opening a citation or the shopping search leaves the app for that external website, which applies its own data practices. Sharing a list uses the destination chosen by the person. Existing guide-catalog hosting and its published diagnostic-data practices remain a separate flow; adding AI does not make the app's existing published privacy label a complete description of the new candidate.
